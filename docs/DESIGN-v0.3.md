# v0.3 设计与交付边界

## 先后顺序

先在独立 v0.2.1 分支完成逐步证据、多指标保留、有界验证反馈，并通过 127 项代码测试和 26 项 Chromium 回归；冻结独立 ZIP 后复制为 v0.3 分支。v0.3 保留全部回归用例，不将未通过的 v0.3 功能混入 v0.2.1。

## 四种对象

Plan (`BoundedProgram`) 仍表示一次预测序列，需要精确行动/结果证据。
SkillSpec (`gs/skill/v1`) 表示参数、已注册启动/局部成功/阶段规则、能力集合、特征集合、评分权重与预算。
SkillRun 保存本次参数绑定、有限阶段、实际效果、访问次数和根预算引用。
SkillSummary/Experience 保存实际局部结果、根任务结果、起止事实、资源成本和中断原因。

## 同构父子

`SkillSession.rootEngine` 与每个 `active.engine` 都是同一个通用 `GSEngine` 的实例。
父层动作是 `callSkill`；执行器只推进一个子 G/S 决策量子，而不是偷偷播放整个脚本。父层在子技能活动期间采用确定性继续调度；子层每步 observe/enumerate/select/gate/execute/feedback。结束时释放执行租约，父层根据更新的世界和经验重新选择。

根预算是同一个对象：物理动作不会在父子两层重复计费，模型请求和搜索/模拟工作分别扣除，运行周期计入两个引擎的实际工作。最大深度 1，拒绝并发世界写入；父取消向子传播。未知执行结果暂停并等待对账，不自动重发。

## 技能 DSL 与生成

四种局部契约：获取一颗、交付、恢复能量、创造采集机会。`place-resource` 和 `wait-access` 等规则实现为授权注册表。谓词/规则、路径规划与位置绑定启发式由开发者编写。默认 G 搜索长度 1–2 的阶段组合，并在确定性世界中模拟局部目标；它不是开放式程序发现或自动归纳世界规律。

Phase 和 SkillSpec 均有有限步数，模型不提供任意 JS、循环代码、工具或自己的验收谓词。场景中坐标保存在 SkillRun 的绑定变量，而不是 SkillSpec。存在候选时按当前世界重新寻路和判断；已声明范围内的守卫时序变化由等待/移动规则处理。

LLM 模式可以提案不同的受限阶段组合与特征/权重。新提案通过结构、权限、局部模拟和版本检查后才试行。相同 ID/version 不允许偷偷替换内容。模型请求错误不切到规则伪造继续；结构/局部验证错误以有限重试返回修正。

## 下行配置的消费者

features 投影真实影响提供给 Jev 的可见结构，运行时安全检查始终使用完整权威世界。
capabilities/phases 实际过滤和组织候选，不是仅写在提示词里。
weights.progress/cost/safety 实际参与离线子选择评分；父层 cost 与 experience 调整技能排序。真实模型看到注册的技能契约，但其遵循情况尚未实测。

这实现了有限配置接口，不是自动感知发明、奖励函数进化或学得的 Q 函数。

## 反馈消费

每次局部结束返回 outcome，记录 steps/energyDelta/attacks/providerCalls/searchNodes 的均值与 M2，按目标、编码器、技能/效用版本和有限关系特征隔离。
取消、外部干预、预算耗尽、未知副作用不增加“无干预成功”证据。执行回执声称 applied 但真实后态不符合物理结果时，暂停，不凭意图增加本地完成次数。

off 不记录也不影响选择；record 记录但不影响排序；use 记录，并在至少两条历史后以收缩后的统计改变根技能排序。真实选择器在 use 模式可见相关统计，在 record 模式不会收到。数据是条件性历史表现，不是因果价值，也没有对未尝试动作虚构安全值。

## 能力与性能分别验收

参数重绑定、父子终止、反馈消费和执行安全是协议/能力验收。完整计划更快或更省能量并不推翻这些协议，但说明 v0.3 不是全面性能升级。实际数据保留在 benchmark-v03.json。

精确暖启动与技能暖启动都继承冷启动数据，不是独立测试样本。镜像等地图在开发中用于调试，不把它们包装成完全未见的统计保留集；额外物体移位/无关障碍也只是有限受控检查。

## 后置

仍无 L3、自动从轨迹抽象阶段、无限分形、跨技能任意递归、根目标自修改、持久化执行恢复、独立实时物理控制或真实模型质量/成本优势证据。完整固定候选高质量真值集、独立开发/校准/保留测试分割仍需后续补齐。
