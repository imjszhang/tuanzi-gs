# G/S v0.4：快速判断的显式任务与组合实验

## 本版交付目标

v0.3.1 先对齐事实、候选顺序与执行证据；v0.4 在这条基线上，将判断从一个隐含提示词扩展为受限任务图，并把不同组织方式接入同一个 GSEngine 和团子世界。本版交付的是可复验的调度、接口和实验设施，不是 Jev 性能或“递归产生智能”的实验结论。

## 改动位置

- `vendor/gs-engine-ts/src/decision.ts`：承接 v0.3.1 中立事实包、来源、版本、种子顺序。
- `vendor/gs-engine-ts/src/judgment.ts`：DecisionTask、DecisionGraph、依赖验证、合批、逐题调度、取消、版本核对、问题与请求预算、逐批证据。
- `src/decision/pipeline.ts`：四种显式问题编译及答案组合；不改写根验收器。
- `src/skills/runtime.ts`：父子运行的选择接口可以直接使用任务图；确定性继续调度和子层单候选快路径保留。
- `src/decision/experiment.ts`：相同 GameWorld 物理、固定 TaskContract 与程序化判断；另有评估专用的小规模 BFS。
- `src/ui/decision-lab.ts`：独立实验副本、目标变化、可选观察、受控干预、截止时间、轨迹与请求证据。
- `server/judgment.mjs`：同源认证后的 Jev 或通用 Chat Completions 判断请求。真实请求均由服务端发出，密钥不进入浏览器。

## 判断任务与图

`DecisionTask` 包含 ID、问题类型/说明/候选量表、明确依赖和允许的绑定操作。`DecisionGraph` 绑定证据快照、根目标版本、问题模板版本，并有有限任务数。图不能携带 JavaScript、访问外部工具或定义新的权限。依赖有环、任务 ID 重复、缺失前置任务或错误回答类型会被拒绝。

同一批只包含已经就绪且依赖上下文一致的问题。各题独立：不能读取同批其它答案。真正有依赖的后续题，在上一批完成、整批响应和快照都通过验证后才构造。错误批不部分提交答案。状态失效、预算耗尽或超时均停止，模型错误不会隐式切回规则。

四种实现：

| 模式 | 题目与执行方式 | 输出组合 |
|---|---|---|
| direct | 单个整体 Choice | 模型/规则从给定候选与 none 中选 |
| batch | 每候选一题适用性 Noul、一题优先级 Score，同一批 | 代码过滤适用性低于 0.5 的选项，按优先级选择 |
| serial | 与 batch 完全相同的问题，逐题请求 | 与 batch 相同组合 |
| dependent | 先合批问逐候选适用性，再把实际通过的候选交给下一轮 Choice | 第二轮真实依赖前一轮结果；none 永远保留 |

0.5 是公开的原型阈值，不是从真实 Jev 风险校准中得出的值。Score 的量表与组合方法由代码声明。复合结果中的 0/1 分布是确定性路由标记，不能当成校准成功率。direct 与拆分方法的算法和题目都不同；只有 batch vs serial 是同题目的调度对照。图结构本身是开发者给定的，LLM 还没有自动生成判断图。

## 信息对齐与证据

规则后端和模型后端接收同一个 DecisionPacket。候选顺序使用稳定 ID 与种子置换，不携带最终规则分数、推荐动作或 BFS 答案。模型与程序共享已计算事实；程序仍负责精确数字、可执行性、一步安全检查、实际世界变更和最终验收。

父子实际技能结果绑定所执行的选择器及问题模板版本；v0.4 的问题模板与 v0.3.1 不混同。单候选使用旧确定性路径时如实记录，混合控制器不冒认全程模型执行。模拟技能的验证范围仍是“规则参考控制器”，不替代模型实测。

## 调度与计量

一次图执行记录独立问题数、批次数、实际依赖波次、每批输入指纹、模型版本、已知 token usage、错误和延迟。依赖波次不是请求数：一波独立问题可能被拆成多次串行调用。父子共享根预算；模型请求按真实请求路径逐批计数；旧计数器含义不作为计费依据。金额没有实测来源时不补造。

批合并不会自动减少问题数、token 或总模型工作量。逐题和合批可能有不同延迟与计费，必须实测。供应商可能自行排队，不能把一次 HTTP 调用假定为所有模型计算免费同时完成。本地规则、搜索、绑定和验证也要记录耗时或工作量。

主游戏保留事件驱动和一层父子深度，不新增实时物理时钟。单层决策图最多 128 题；主游戏一次判断最多 96 批、128 题，受根请求预算再次限制。实验副本使用共同的 512 次请求和 512 题上限；设定的墙钟截止覆盖整局实验，不是给每一步重新发一份时间预算。

## 游戏实验与观察

新面板使用同一 GameWorld 的冻结小地图，与上方主游戏世界隔离。四个不可修改的任务契约：立即交付、交付并保留两颗、交付时能量至少 35、采集后交付并保留资源。前三个具有相同物理起点，用不同目标检查选择是否变化。

可选 `observe(resources)` 真实更新知识版本和下一次可见的能量/背包/交付字段，不推进物理回合。它有观察预算，产生后续判断成本，不是完全免费的能力。可执行动作的存在与参数仍可见，故该实验不是严格无信息的 POMDP；只验证显式缺失字段、观察与重新判断路径。完整真值用于安全和审计，不直接给选择器。观察动作尚未泛化接入全部旧技能。

采集链的干预脚本在第 3 个物理动作后在 (3,8) 加障碍，记录是否实际编辑成功。四种方法面对相同任务与脚本。合成延迟只用于离线判断后端，明确不是 Jev 测速。按下取消后不再接受迟到结果，也不继续执行旧计划。

## 参考求解与评估范围

小规模完整可见、静态夹具可以调用独立的单位步数 BFS。仅队列按层搜索找到目标时标记 OPTIMAL，状态/队列预算耗尽标 EXHAUSTED，不冒称“当前最好就是最优”。隐藏观察或受干预任务不直接引用全知静态最优值。长任务暂不展示未计算出来的理论最优。参考求解只在结果生成后执行；在线单步模拟数单独记录。

标准面板四组对照完全离线，同一规则判断器并不变聪明。批处理若减少请求只支持调度结论，不支持模型准确率或认知提升。真实模型路径允许单独运行，并有显式 `--live` 的 CLI；无凭据或未选择实网时保持 NOT_RUN。开发夹具、镜像和已有地图均参与过开发，不包装成独立保留集。
