# 别让团子饿死 · G/S LAB

一个真正接在 **G/S Engine v0.1** 上的 TypeScript 交互游戏。你改变世界，Agent 从已有能力中选择行动；必要时请求策略修复，并用实际结果验收。

**默认离线运行。** 规则选择器与预置修复模板被明确标注，不冒充 Jev 或 LLM 的表现。项目包含真实模型接入代码，但本交付没有调用付费模型。

## 直接玩

**打开根目录中的 `play.html`。** 这是单文件版本：样式、JavaScript、图标与地图绘制全部内嵌，无外链、无字体下载、无 API Key，无需 Node 或 npm。

下载后用桌面浏览器打开；聊天软件、邮件客户端中的 HTML 预览可能不允许运行脚本。若本地浏览器禁止 file://，使用下面的本地服务启动方式。

## 启动完整项目

需要 Node.js 22 或更高版本。已经包含编译文件，**试玩和启动服务不需要先安装 npm 依赖**。

```bash
cd tuanzi-gs
npm start
```

打开终端显示的本机地址，默认：`http://127.0.0.1:4173`。

端口被占用时，在 `.env` 中设置 `PORT=4174` 后重新启动，或使用你的操作系统支持的环境变量方式设置。服务只绑定 `127.0.0.1`；它不是已经公开部署的网站，也不应直接暴露在公网。

## 三个关卡

| 关卡 | 要观察的机制 | 默认离线实现 |
|---|---|---|
| 01 日常采集 | 现有能力足以完成任务 | 候选生成 + 启发式选择，不修复策略 |
| 02 近路被堵 | 路径失效不等于需要昂贵推理 | 确定性 BFS 绕路，不修复策略 |
| 03 守卫果园 | 原有策略没有适用候选 | 试行预置诱饵策略，启用已有 drop 能力 |

守卫果园开局背包有一颗浆果，作为可用资源。诱饵玩法没有增加新物理能力：程序原本就实现了 `drop`，初始采集策略没有启用它。离线 Planner 选择一个预先写好的策略模板；真实 LLM 接入后，也只能修改受限 Policy，不能生成并执行任意代码。

初始世界与离线控制器没有随机分支，因此可以重现实验。地图装饰与动画不参与决策，截图不能证明模型能力。

## 怎么操作

按 **开始观察** 连续推进，或按 **单步** 执行一个 G/S 决策周期。单步可能提交一个策略，不一定产生物理动作。切换速度改变界面节奏，不改变世界物理规则。

**观察工具**查看格子信息；**浆果工具**点击空地新增浆果，先点已有浆果再点空地可搬动；**障碍工具**放墙；**守卫工具**移动唯一的守卫；**擦除工具**清除浆果、人工障碍或守卫。小窝、团子当前位置、湖水和天然岩石不可直接编辑。

**存快照**保存当前世界和策略；**从这里重来**创建一个新运行并恢复这两者。快照仅在当前页面内保存，刷新页面不会保留。需要留档时导出 JSON。

**对照**从保存的同一世界快照分别运行“固定规则策略”和“同一选择器 + 预置修复”。两组都从初始采集策略开始，不继承保存快照中的已升级策略。对照不会调用外部服务，也不是模型成本或性能基准。

**回放**读取每次动作完成后的快照，不重新执行动作，不调用模型。玩家干预的完整记录在导出的 `interventions` 中；回放画面以各动作后状态呈现，不逐条播放所有干预事件。

键盘：`Space` 开始/暂停，`→` 单步，`R` 重置。输入框、按钮焦点或对话框打开时避免抢占原生键盘行为。

## 游戏规则

- 每个实际动作消耗 1 点能量；等待也算动作。暂停、模型请求、策略更新、回放和玩家编辑不消耗游戏能量。
- 吃一颗浆果消耗背包资源，恢复 32 点能量，上限 100，然后扣除本回合的 1 点能量。
- 背包容量为 3。只有回到小窝执行交付，才计入目标。
- 目标是活着交付至少 5 颗浆果。最多 180 个动作。
- 清醒守卫周围曼哈顿距离 2 以内的格子视为危险区，不生成不安全路径。若守卫主动靠近到距离 1，会造成 14 点能量损失。
- 守卫追逐 9 格内的投放诱饵；每个行动回合移动一格。吃到诱饵后停留 18 回合，再返回原驻点。天然浆果不会自动触发追逐。
- 草地、湖水、天然岩石与基础能力由代码定义，Policy 不能修改世界规则或根任务。
- 自由编辑可能造成无解局面。停止运行或修复失败是合法结果，不强行宣布成功。

## 如何观察 G/S

右侧展示的是真实运行对象，不是额外编造的思考过程。

**G 候选**是当前快照下 `Domain.enumerate()` 形成的动作实例。**S 判断**是 Selector 返回的相对选择与适用性信号。**G 修复**是 Planner 提出的受限 Policy 更新。**反馈**来自真实执行后的状态，不由模型宣布任务成功。

离线百分比是启发式分数归一化后的展示权重；不是模型概率、胜率或经过校准的置信度。真实模式的 Jev 选项概率也不等于动作真实成功率。

计数说明：`S 判断`统计选择接口调用，`G 修复提案`统计修复请求，`远端请求`统计浏览器向本地模型代理提交的请求。远端请求不等于成功计费次数；服务端校验拒绝、超时等会造成差异。用量只记录提供商实际返回的 token，未知金额不伪装成零成本。

## 真实模型模式（可选）

根目录复制 `.env.example` 为 `.env`，填入自己的配置，然后重启服务。

```dotenv
PORT=4173
TYPESAFE_API_KEY=your-typesafe-key
JEV_MODEL=jev-1.13.0

LLM_API_KEY=your-provider-key
LLM_MODEL=your-model-id
LLM_URL=https://your-provider.example/v1/chat/completions
LLM_JSON_MODE=true
MAX_SERVER_CALLS=200
```

这里的 `LLM_URL` 是完整的 Chat Completions 兼容接口地址，不是基础域名。它只能从服务端配置，浏览器不能提交任意目标地址。需要提供商支持 `messages` 和 JSON 文本响应；对不支持 `response_format` 的提供商可设 `LLM_JSON_MODE=false`，但仍必须返回符合约定的 JSON。没有覆盖所有厂商的特例。

配置后在界面中打开 **模型连接**。提供四种模式：离线规则、离线固定策略、Jev + 预置修复、Jev + LLM。配置不完整的选项不可选。真实模式需要勾选发送游戏状态及费用确认，并重新开始当前关卡。

密钥只由服务端读取，不进入浏览器 Bundle，不写入轨迹。前端持有的 `x-gs-token` 是本地服务的临时访问令牌，不是提供商密钥。

Jev 适配器沿用提供的引擎接口：一次请求中分别询问 Choice 和每个候选的 Noul，不让同批问题读取彼此的答案。LLM 返回 JSON 策略提案，经过字段、能力、版本校验后才允许提交。超时或接口错误停止运行，不静默退回离线脚本。

**实网验证边界：** Jev 与 LLM 真实账户尚未测试。本地 HTTP 假服务测试了 LLM 请求形状、JSON 解析、用量返回、越权字段拒绝和预算；这些测试不证明任何真实模型的准确率、延迟或费用收益。

## 项目结构

```text
tuanzi-gs/
├── play.html                     # 自包含单文件试玩版
├── public/                       # 本地服务使用的界面构建文件
├── src/
│   ├── game/
│   │   ├── types.ts              # 世界、动作、策略类型
│   │   ├── world.ts              # 物理规则、编辑、BFS、世界版本
│   │   └── domain.ts             # Domain 接口、执行与验收
│   ├── runtime/
│   │   ├── controllers.ts        # 明示的离线替身及远端适配器
│   │   └── session.ts            # 组装原版 GSEngine、轨迹、对照
│   ├── ui/
│   │   ├── renderer.ts           # Canvas 地图与动画
│   │   └── icons.ts              # 内嵌矢量图标
│   └── main.ts                   # 交互与观测界面
├── vendor/gs-engine-ts/           # 原始 G/S 引擎，源码未改写
├── dist/                         # 编译后的模块和 TypeScript 声明
├── server.mjs                    # 仅本机的 HTTP / 模型代理
├── scripts/build.mjs             # 编译与零依赖浏览器打包
├── scripts/browser-smoke.py      # 可选的 Playwright 交互检查
├── tests/                        # 游戏、执行边界、服务端测试
└── reports/                      # 测试记录与界面截图
```

主要游戏和运行代码为 TypeScript。极薄的本机启动器与构建脚本使用 Node.js ESM；没有引入 React、Canvas 游戏框架或运行时 npm 依赖。

## 开发与测试

构建只需要项目指定的 TypeScript。修改源码后重新构建：

```bash
npm install
npm run build
npm test
```

也可使用 `npm run check` 一次完成构建与代码测试。`npm test` 本身测试已有构建文件，不自动下载依赖或调用外部模型。交付包含原引擎 33 项测试与新增游戏/代理 33 项测试，共 66 项。

浏览器检查可选，需要 Python Playwright 及 Chromium：

```bash
python scripts/browser-smoke.py
```

通过 `CHROMIUM_PATH` 指定浏览器路径。当前运行环境禁止浏览器 URL 导航，因此浏览器测试将**最终单文件 HTML 的原始内容直接装载到 Chromium 页面**，执行真实 DOM、Canvas 和交互。没有关闭浏览器安全策略。HTTP 服务、授权边界和模型假服务另由 Node 测试验证；并未声称完成浏览器到真实模型服务的端到端测试。

## 边界与后续扩展

本版验证的是可运行机制：同一 Agent 串行决策、模型响应绑定状态版本、执行点复核、幂等回执、受限策略提交、独立验收与可检查轨迹。引擎在候选或规划期间遇到玩家改动，会丢弃过期结果。

本版不包含任意技能代码生成、自动技能发现、在线模型训练、自动多层分形、持久化崩溃恢复、多人同步或真实模型性能证明。Policy 仅允许预先定义的模式、已实现能力和有限参数。根权限、任务与验收条件保持不变。

本机服务含同源检查、Host 白名单、临时访问令牌、请求大小限制、串行调用限制和提供商请求次数上限。它仍是个人实验工具，不是互联网生产服务；请求次数上限不是美元硬预算。需要额外控制台预算、身份认证、计费对账与生产级恢复时，应在此基础上独立实现。
