# v0.2.1 → v0.3 验证说明

## 顺序与阶段门

v0.2.1 在独立工作目录完成 127 项代码测试和 26 项 Chromium 检查后冻结为独立 ZIP；随后才复制进入 v0.3。阶段门 `reports/GATE-v021.json` 保留原始结果。通过这些测试不是无缺陷证明。

v0.3 当前代码测试：178 项通过、0 失败。包括原 127 项及新增 51 项：39 项技能/层级/经验相关检查，12 项新模型桥接与本地 HTTP 检查。构建同时编译游戏和通用引擎，测试不使用旧的 vendor dist 冒充修改后代码。

v0.3 浏览器检查：31 项新界面检查 + 26 项旧程序界面回归；原始 JSON 和逐项记录在 reports。最终阶段门与干净解压复验以 `reports/GATE-v03.json` 为准。

## 本次发现并修复的关键问题

- 原计划最后一个动作被替换后，根任务成功不能给旧计划记精确成功。计划证据与实际任务结果分别保留。
- 更短计划不自动淘汰能量更多的计划；只有同目标/条件的多指标支配才参与自动淘汰。
- 可恢复的结构/模拟拒绝回传生成器，最多三次提案尝试（包括首次），每次计预算；网络故障、取消和未知副作用没有隐藏重试。
- 子技能只在“意图动作”和实际世界效果对应时记录完成；applied 回执本身不是成功事实。
- 父子共享根资源；未知子执行结果令根暂停，不能转成普通失败后悄悄继续。
- 相同技能 ID/version 不可悄悄更换规范；中断与外部编辑不增加无干预成功次数。

## v0.3 能力验收

局部“创造采集机会”在交付 0/5 时可以成功返回父层；父层随后选择采集/交付子技能，最终才验收根任务。

同一生成技能 ID/version 在标准果园、镜像、无关障碍和一个受控物体移动变体中重新绑定目标，不携带旧坐标；这些有限测试不是所有环境的泛化证明。原语规则、参数绑定启发式、语法与局部谓词都是显式开发者知识，只有阶段组合被搜索生成。

经验实验使用实际子运行采集 3 次无效技能结果和 3 次有效技能结果。相同训练记录分别载入 off/record/use 组，前两组仍选原优先方案并局部失败；use 组选择实际更有效的方案并局部成功。它证明反馈被消费，不证明统计量是因果价值，也不证明 Jev 已学会这些偏好。

真实模型路径中，use 才发送相关经验；record 不发送。提供商测量采用单次尝试账本 `hierarchy.providers`；`rejectedUsage` 是拒绝诊断的引用，不能再加到该账本上重复计费。金额未知时保持 null。

## 模型验证范围

没有真实 Jev/LLM 调用。本地 HTTP 模拟服务测试了同源认证、预算、受限 JSON、被拒提案和修正反馈、实际模拟响应 usage、未知候选、参数限制以及失败不降级。

默认 `npm run bench:models` 产生 `NOT_RUN`，不会读取结果来补造模型性能。有凭据且显式添加 `--live` 才执行付费请求。完整高质量真值集、统计风险阈值校准、预先隔离的开发/校准/测试划分仍未完成，不能把接口和脚本视为收益已验证。

## 浏览器验证方式与边界

环境 Node.js 22.16.0 / TypeScript 5.8.3 / Chromium。自动化用 `set_content` 装载实际单文件字节。跨页面持久化用注入的 Storage 夹具测试序列化；单页重置复用为实际浏览器操作。没有宣称已测试公网部署、HTTP 页面导航、Safari、Firefox 或真实 file:// 刷新持久化。HTTP 路由独立由 Node 测试。

检查包含桌面和 390px 移动端、父子状态、预算显示、参数化 JSON、局部结果、完整任务、镜像复用、编辑后反应、回放只读、快照新运行、四组对照、经验模式切换、无密钥禁用真实请求，以及无外部网络和无未捕获错误。
