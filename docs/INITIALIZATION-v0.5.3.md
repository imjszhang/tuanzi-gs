# v0.5.3 — 开局先 G，再由 S 行动

## 范围

只改变 `kind=game, controller=adaptive` 的新会话启动顺序。固定判断实验和旧离线参考控制器不新增 G。新建实验、查看状态、打开网页和订阅流仍没有模型副作用。

首次 `start` 或 `step` 后，先检查终局/预算，再从当时的允许环境取得观察，以 `cause=initial_environment_review` 调用现有有界 G/S 解析循环。创建以后、启动以前发生的合法环境编辑，以及 action=0 的脚本干预，均进入这份当前快照。

```
创建 → ready（0 请求）
开始 / 单步
  → 检查起点与根预算
  → G 研判允许的初始环境
  → 同一 schema 校验；必要时有界定点格式纠错
  → 上层 S 选择初始决策条件（仍可 none，必要时递归）
  → 应用初始上下文 / 选项 / 局部阶段
  → 动作层 S 判断
  → 版本与合法性复核 → 至多一个实际动作
```

第一轮 G 不是对一个虚构 S 失败的修复。`answer=null`，首次 `previous`、实际动作历史和 S 判断历史均为空。初始 frame 是未执行的 S 输入草案；G 可以看到白名单中的更广环境和公共规则，决定如何为 S 设置第一轮局部问题。假设不变成事实，合法程序不等于正确策略。

## “一次”与完成条件

正常初始化为一次 G 生成、一次元层 S 选择；不是规定最多只能调用一次模型。结构错误、元层弃权仍沿用现有纠错/递归额度。全部请求记入原有 `maxGCalls`、`maxRequests` 与墙钟预算。

初始化只有在合法修订经上层 S 选中、根层决策条件提交之后标为 ready。G 返回文本、流式 complete、JSON 合法都不足以独自完成初始化。

G 也可以在查看当前快照后明确保留原决策条件。初始 frame 的 `startupReview.state` 从 pending 进入 committed，表示完成这一运行契约，不是策略正确认证。后续仅改标题或重置动作计数，仍被现有等价性检查拒绝。

一次 CLI `step` 沿用“至多一个物理动作”的语义，可包含初始化和首个动作。它不是只做初始化的独立命令。G 尚在生成时动作数为0；若完整生成、校验、选择均成功，同一次单步可能随后执行一个动作。

## 生命周期

- 新会话、从检查点产生的分支，均重新研判各自起点。继承的自身记忆可按既有配置供 G 参考，但不替代本次初始化；不恢复父调用栈。
- 暂停 / 继续、后续单步、网页重连、幂等命令重放不会重跑初始化。普通反馈仍可触发新的 G 调整。
- 初始化期间，或首个动作提交前，世界版本变化使旧结果失效。保留全部已用预算；下一量子在新快照重新研判，不使用旧输出推进。
- 首次 G 请求失败、格式纠错耗尽、上层拒绝、取消或额度不足，不回退到默认 S / 规则动作。
- 起点已成功、能量耗尽或物理回合已结束，由根验收直接结束，跳过不必要的 G。取消发生在开始前也不请求模型。
- host 的 pause 仍在当前决策量子结束后生效，该量子可能完成初始化和一个动作。cancel 向在途树传播，不承诺回滚。

## 审计与 UI

新增 `diagnostics.initialization`，字段包括：

- `policy: g-before-action/v053`
- `status: pending | reviewing | ready | failed | skipped-terminal`
- `reviewCount`：进入初始化流程的次数；世界变化重新开始时增加，不是 G 请求总数。
- `reviewedRevision`、`policyVersion`：最近完成初始条件提交所对应的版本。
- `reason`：中断/失败原因。

事件：`initialization_started`、`initialization_ready`、`initialization_invalidated`、`initialization_failed`、`initialization_skipped`。沿用同一个 runId 和事件序号。

开局 G 的账本 `purpose=initialization`，原因 `initial_environment_review`。格式纠错仍为 `purpose=output-repair`，`originalCause` 保留初始化来源。后续 G 为 adaptation。流式卡、历史与诊断显示“开局环境研判”；不增加第五个页签，不重复调用模型，不执行半份 JSON。旧日志没有初始化记录时不补造。

## 未改变的信息边界

无解法示例、参考路线、优化站位、模拟收益或规则推荐动作。G 只拿到运行原先允许获取的公开信息与自身证据。S 仍然信息有限、允许犯错与弃权；G 仍然可能判断错误。此次初始化不是先计算最优路线，再让 S 跟随。

## 限制

这是启动顺序与生命周期修订，不是保证 G 正确理解初始世界的证明。未调用真实 Jev/LLM；需要实网测试质量、延迟与任务成功率。增加开局 G 会增加首个动作之前的延迟和预算占用；对照旧成绩必须计入这部分成本。
