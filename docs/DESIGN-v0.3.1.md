# G/S v0.3.1 — 信息对齐与决策审计

## 本版范围
保持 v0.3 父子 G/S、固定根目标、执行租约、取消和技能契约，修正评估条件，不增加递归深度。

1. `DecisionPacket` 是版本化事实包。父层与子层的规则控制器和模型适配器读同一个 packet。规则评分函数只消费其中的事实与明确权重，不读取额外世界对象或隐藏排名。
2. 父层移除进食/交付时机的偏好过滤：满足启动条件的候选仍在，是否值得执行由 S 决定。仍有限域：已注册技能、可达浆果、按稳定 ID 限 24 个浆果目标；完全相同状态下刚失败的调用会暂时排除。子层仍受已注册阶段约束；这不是全局完备候选集。限制写入 `scope`，剪枝写日志。
3. 候选先按 ID 规范化，再用固定种子打乱。规则分数不会进入提供商请求，UI 可单独展示选择结果。相同状态与种子可重跑，另有换种子敏感性测试。
4. 子候选事实记录当前/行动后路径距离、阶段里程碑、一步模拟后的能量/受攻击变化、危险距离和已访问次数。一步模拟是已知世界提供的事实，不是动作长期成功率。
5. 规则模拟结果带 `authored-reference-controller-only`、规则与事实版本。实际子结果带具体选择器、问题版本、事实版本及 `actual-controller-run`。无模型请求的单候选路径不会被归给模型。技能累计成功不等于跨模型认证；应看 `executions[].identity`。
6. 每次选择生成 `DecisionAudit`，记录来源、问题包、输出、时延和请求数；父层确定性继续单独标记。selected 表示选择输出，不等于已执行。实际效果仍以 transition/receipt 为准。

## 可重跑基准
`node scripts/benchmark-v031.mjs`：4 张开发地图 × 2 个候选顺序种子 × 2 种控制器（本地规则与只读同一 packet 的模拟提供商）。比较物理轨迹，真实模型调用 0。规则输出是参考，不是最优真值。

新增测试不取代原 178 项测试。离线与模拟接口不能证明 Jev 准确率、价格、延迟或成本优势。原地图依然属于开发回归集，不能声称未见泛化。
