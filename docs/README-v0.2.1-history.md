# 团子 / G/S Lab v0.2.1

**从预置模式切换，走到「受限程序合成 → 模拟验证 → 实际试行 → 精确条件复用」。**

这是原 v0.1 的增量版本，不是重写的独立演示。保留可干预游戏、TypeScript G/S Runtime、Jev 接口、版本/权限/预算保护、快照与回放，新增有限程序、循环诊断、验证记录与公平对照。

## 直接运行

零密钥试玩：用现代桌面浏览器打开 `play.html`。无网络依赖，无外部模型调用。

完整本地服务：Node.js 22 或更高版本，解压后执行：

```sh
npm start
# 在浏览器访问 http://127.0.0.1:4173
```

已附编译文件，**试玩和 `npm start` 不需要安装依赖**。修改 TypeScript 源码后：

```sh
npm install
npm run build
npm test
npm run bench
```

`npm run build` 同时编译应用与内嵌引擎，确保引擎回归测试使用的是修改后的版本。运行时没有第三方 npm 依赖；开发依赖为 TypeScript 5.8.3。浏览器自动化是可选开发工具，不影响运行游戏。

## 先体验这个闭环

1. 默认打开「守卫果园」，运行方式为「程序搜索 + 技能记忆」。点击「单步」，日常规则发现没有适合的动作，搜索器开始组合已有原语。
2. 新程序通过模拟检查，出现策略 v2，但世界尚未执行动作。下方可查看真实程序 JSON。此时记录为「试行」，不是已学会。
3. 点击「开始观察」。每个动作执行前重新检查状态、版本和合法性。实际交付五颗且存活后，程序才成为可复用记录。
4. 重置同一个关卡，继续运行。命中精确条件的已验证程序后会重新模拟，但不再搜索。`本轮新搜索=0`，`技能命中=1`。
5. 切换「镜像布局」或编辑世界，旧记录不能直接套用。可能需要新搜索；预算内搜不到会明确停止。
6. 点「对照」，查看完整规则基线，不把“关掉原来的规则让它失败”当作新引擎的证据。

暂停不消耗世界能量。世界仍是动作驱动的确定性环境，不是独立实时物理循环。自由编辑可能产生无解或当前搜索预算无法解决的地图。

## TypeScript 接入点

通用内核不认识浆果、守卫或 LLM SDK。本版新增两个可选 Domain 接口：

```ts
assess?(context): { kind: "repair" | "pause"; reason: string; evidence: Json } | null;
validateProposal?(nextPolicy, context): readonly string[];
```

`assess` 是每步决策前的诊断入口；`validatePolicy` 保留结构与权限检查；`validateProposal` 只对进入系统的新提案做昂贵验证，不能把环境变化错误解释成策略结构非法。

内核还导出 `BoundedProgram<A>`、`parseBoundedProgram` 和 `inspectProgram`。搜索与程序记忆目前位于游戏适配层，**不是通用 G/S 内核已经获得了任意领域的技能学习能力**。

## 程序 DSL 的边界

```ts
type BoundedProgram<A> = {
  schema: "gs/program/v1";
  id: string;
  title: string;
  startTurn: number;
  steps: { expect: string; action: A }[];
};
```

只支持有限序列。每步可选的能力为移动、拾取、吃、交付、放下、等待。移动仍然一次一格。最多 180 步，并受本局剩余动作预算限制。没有 `eval`、任意代码、无界循环、模型自定验收器或递归子调用。

`expect` 是诊断用双 32 位校验值，不是密码学凭证，更不授予执行权限。程序进入时逐动作模拟；实际执行还要经过原语合法性、当前世界版本、策略版本和幂等检查。技能检索另外比较完整条件字符串，并再次模拟验证。

默认离线 G 使用固定声明的有界搜索组合：task/80、explore/80、explore/160，各自最多 16,000 个展开节点，深度最多 150（也受剩余世界预算限制）。第一组找到有效程序就停止。搜索启发式由开发者编写，但**行动序列不是预写模板**。搜索过程只在复制的模拟状态上运行，不消耗真实世界能量。

这不是最优或完备搜索。`budget` 或 `exhausted` 只描述搜索过程，不能证明世界无解。模拟器完全已知是本实验的便利条件，不能直接套到未知真实环境。

## 程序记忆

生命周期：`trial → verified / quarantined`。更短且实际成功的程序可以替换精确相同条件下的长程序；不跨任务比较。

- 模拟成功不等于验证记录可复用。必须由实际游戏根验收器确认任务成功。
- 用户干预会单独记录；不把干预造成的失败混作无干预效果。
- 中途恢复快照不能补造未观察到的成功前缀。
- 清空记录后不会在结束时伪造「已保存」。
- 本版匹配精确初始物理条件、规则版本、资源和剩余预算；**不是对相似情境的通用技能迁移**。
- 通常存储于当前浏览器 localStorage。浏览器禁止该存储或配额不足时，界面提示仅保留在内存，可导出 JSON。记录不具有防篡改审计性质。

## 真实模型模式（需要自行配置）

复制 `.env.example` 为 `.env`，仅保存在服务端：

```dotenv
PORT=4173
TYPESAFE_API_KEY=
JEV_MODEL=jev-1.13.0
LLM_API_KEY=
LLM_MODEL=
LLM_URL=https://your-provider.example/v1/chat/completions
LLM_JSON_MODE=true
MAX_SERVER_CALLS=200
```

随后 `npm start`，打开本机页面，在「模型连接」里选择并确认费用说明。

- `Jev + 本地程序搜索`：S 使用 Jev，G 仍是本地搜索与程序检索。
- `Jev + LLM 程序生成`：S 使用 Jev；未命中记忆时 LLM 返回严格 JSON `{title, actions}`，服务端自行编译、模拟和校验。
- 旧版 Jev/LLM 配置模式仍保留用于历史对照。

生成程序接口为 `POST /api/program`，其他为 `/api/select`、`/api/plan`。全部仅接受本机 Host、同源 Origin 与会话 token。密钥不写入浏览器、轨迹或程序。接口失败、无效程序、不完整方案不会偷偷退回预设模板。

本次**没有调用真实 Jev 或 LLM**，只验证了本地模拟响应与协议。不能保证模型能一次生成正确的完整动作程序；失败需要检查输出与提示，而不是当作已完成。模型服务输出的 token 才计入用量；费用未知就不填零。服务端上限是请求次数，不是货币硬预算。

接口形状核对参考 TypeSafe 官方文档：
- https://docs.typesafe.ai/primitives/choice
- https://docs.typesafe.ai/concepts/state
- https://docs.typesafe.ai/sdk/javascript
