# v0.5.0 发布与迁移

## 核心变化

1. 新增无参考解的自主控制器 `adaptive`，S可不完整、弃权和犯错；G据实际证据调整上下文、选项、局部问题与阶段。
2. 调整方案由上层S选择；上层判断也可被G重构，最大元层深度可设为1–3（根层为0），共享根预算。
3. G不是参考规则的包装：无已解技能示例、无参考控制器模拟成功准入、无程序化最佳目标/站位绑定、无参考评分或旧技能记忆。
4. S的高置信度错误也可由实际停滞、受击、阶段耗尽/完成、外部变化触发G；不是只处理none。
5. 相同世界中有实质上下文变化可以重试；仅改标题或重置同一阶段计数不算新决策。S仍可拒绝G提出的方案，不强制次高动作，不隐式回退。
6. 参数合法性和实际任务验收不变；G陈述为未验证假设，试行、局部结果、根成功分开。
7. CLI/API/网页共享原runId，显示调整前后、递归层级与模型/本地来源。

## 有意不兼容的地方

- `--kind game` 不指定controller时默认adaptive。
- 原 `hierarchy/program/rules` 是离线参考。实网配置会被拒绝，不静默替换。
- `/api/select`、`/api/plan`、`/api/program`、`/api/reactive-select`、`/api/reactive-plan` 返回410。新的G仅在服务端自主会话内调度，没有允许操作者注入任意修复上下文的公开端点。
- `play.html` 与`/`标为历史离线参考，旧模型选项禁用；自主模式使用`/lab`。
- 跨参考/自主模式的记忆继承被拒绝。只复制世界快照的分支仍可创建，保留lineage，不冒充独立冷启动。
- 现有判断组合夹具继续用固定事实/规则基线，它不等同自主G重构任务。

旧调用模板应把`--controller hierarchy --backend jev --generator llm`改成`--controller adaptive`，并明确G/递归预算。不能保证新路径复现旧的通关表现，因为已经移除了帮助解题的参考控制器和战术绑定。

## 启动

解压到新目录，保留自己的`.env`、`.gs-lab/exports`与代码差异：

```bash
npm start
# http://127.0.0.1:4173/lab
```

Node22+，已含编译文件。修改源码才需要npm install后build。可选`LLM_THINKING`和`LLM_REASONING_EFFORT`仅在配置后透传，供应商是否接受需要真实配置验证，本次没有真实模型请求。

## 看什么

概览看S/G当前处理和世界动作；判断过程看真实选择及none；诊断看G提出与实际应用的条件差异；配置看自主/参考路径与额度。页面本身不会额外调用模型。

可以先运行`npm run bench:v05`：这是有标注的合成控制流夹具和本地后端测试，不是模型通关。真实模型需要自己的服务端凭据和明确授权。

## 已知限制

- 没有真实Jev/LLM效果结果。不得把通过代码测试说成概率判断问题已消除。
- 新本地后端只用于操作与协议检查；不是通关器。四张地图在有限测试预算下均未交付成功，记录随包保存。
- 有限阶段程序与有限元层递归，不是自动生成无限层级、自动技能抽象或训练模型权重。
- 停滞检测是开发者启发式，可能触发不必要审查，也可能漏检问题。
- 自主路线上不使用寻路或多步参考模拟；G/S必须自己利用公开规则与观测，效率可能下降。
- 活跃会话不能跨服务重启恢复；只读导入不能恢复调用栈。进程级请求上限不是金额上限。
- 可信本地使用，不是公网多租户或恶意代码隔离沙箱。

## 测试迁移透明性

旧版中要求带参考辅助的实网规划端点成功的测试不再适用。原测试源归档在`tests/legacy-v04`，替换为410拒绝、零供应商调用、无答案泄露、版本/权限和新G/S恢复测试。历史参考算法本身、引擎约束与HTTP控制测试继续运行，不通过删除失败用例声称旧接口仍兼容。
