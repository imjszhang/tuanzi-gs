# G/S v0.2：程序合成与精确条件复用

## 本版研究问题

当已有日常规则无法继续时，是否能组合已有原语形成一个有限程序，经固定验收器模拟检查并实际完成任务后，在精确相同条件下免去下一次新生成？

本版对这个受控问题给出了可执行实现。它没有把这个结果扩大为认知架构完备性或自主进化证明。

## 控制流

```
观察 → 任务验收 → Policy 结构检查 → Domain.assess
                                       ↓
                           有效候选 → S → 执行器 → 真实反馈
                                       ↓ 需要修复
                         精确条件技能检索与再次验证
                             命中 ↙         ↘ 未命中
                              │      有界搜索 / LLM 原语提案
                              │             ↓
                              └──→ 有限程序编译与模拟验证
                                            ↓
                                校验依据未过期 → Policy 提交
                                            ↓
                              下一轮重新观察并实例化所有原语
                                            ↓
                                 每步检查程序 expect 与合法性
                                            ↓
                           实际根任务成功 → 程序记录晋升 verified
```

## 引擎和领域边界

通用引擎增加诊断和提案验证两个可选钩子，并提供泛型的有限程序契约。领域层负责真实物理规则、程序动作解析、模拟器、根验收、循环指纹与具体生成器。UI 观察事件，不决定验收结果。

根目标、预算、世界规则、允许的基础能力不在模型可编辑空间。G 只能产生可校验的数据。

## G 是如何得到新动作序列的

`search.ts` 枚举当前全部合法原语，复制状态执行模拟，以固定声明的启发式评分做 beam search。它不调用诱饵选点算法、不匹配地图名称、不使用预设诱饵步骤。启发式是开发者提供的搜索知识，不是学出的价值函数。

有界搜索配置：task/80、explore/80、explore/160，逐次尝试至找到通过根目标的序列；每次展开上限 16,000、最大深度 150。搜索会定期让出事件循环并检查取消。

这仍依赖一个已知、可复制的确定性世界。未来真实环境需要不同的预测/验证机制，不能把模拟成功直接当成环境成功。

## S 的含义

新模式每步实例化相同的合法原语集合。默认 S 是确定性程序跟随器/日常规则选择器，不冒充 Jev。在有效程序存在时它从真实候选集中选取当前步骤对应的动作。Jev 接入后可以建议其他合法候选；偏离程序会导致下一轮前置检查失败并重新请求处理，而不是绕开权限。

这是一种“有限轨迹计划 + 逐步闭环复核”，不是完整的条件策略或新的子 Agent。

## 循环诊断

比较近期同一策略版本下的物理状态，保留位置、资源、浆果、守卫位置与计时、诱饵、地形和人工障碍；忽略仅导致永不相等的时钟、revision 和能量计数。相同局面在连续窗口重复至少三次、且已有至少四个动作时触发修复。外部编辑打断连续窗口。

因此单步更接近临时目标，不再能永久掩盖两格往返；守卫计时变化的合理等待又不会被当成完全相同的状态。该诊断不是所有停滞模式的完整识别器。

## 提案验证与活跃状态失效分离

`validatePolicy` 检查结构与权限，`validateProposal` 对新的程序做完整模拟。活跃程序遇到状态改变，由 `assess` 路由修复，而不是把一个过期程序错判为结构非法后永久 fault。

提交策略仍需世界 revision 与策略版本匹配；策略提交和物理执行是两个不同的 step。每次执行仍走 root executor 和原有预算，不额外生成子预算。

## 经验的实际更新路径

程序模拟成功后仅为 trial。实际执行从本次提交开始，根任务成功且期间没有玩家干预，才晋升 verified。精确条件复用需要 ruleset、完整起始条件和剩余预算一致，并再次模拟。候选记录不能被检索为已验证技能。

失败、环境干预、未完成、中途恢复、清空记录均有独立处理；没有为尚未观察到的轨迹补写成功证据。记录存储可失败，UI 报告内存退化。当前不提供防篡改或跨设备同步。

## 协议与代价

保留 `Engine.counters.modelCalls` 作为旧接口的预算计数，它统计 Selector/Planner 接口调用，离线也可能增长，**不等于外部计费请求**。新增 `planning.providerS/providerG`、`searchRuns/expanded/generated/searchMs/skillHits` 分别记录真实请求尝试、本地搜索与记忆命中。日志里的 provider usage 仅来自实际返回字段，金额未知时不补造。

## 留待后续

有限程序仍无分支、循环与子程序调用；精确记录不是可迁移的抽象技能。没有独立 L2/L3、感知或奖励权重优化、价值表、在线训练。不能把本版技能缓存命中叫作自动分形或自我进化。
