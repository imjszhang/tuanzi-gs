# 团子 / G/S Lab v0.4

**将快速判断组织成有证据、有依赖、有预算的有限任务，并在同一个游戏里比较结果与开销。**

## 打开与启动

直接用浏览器打开 `play.html`，可离线试玩和运行全部规则对照，无需账号或 API 密钥。聊天软件预览可能禁用脚本，请在本地浏览器打开。

完整项目需要 Node.js 22+，已包含编译文件：

```sh
npm start
# 打开 http://127.0.0.1:4173
```

## 两个实验区域

上方仍是可编辑的团子世界与父子 G/S。打开“模型连接”，可以为技能模式选择直接 Choice、独立拆分合批、同题逐题请求、真正依赖前轮答案的两阶段判断，或保留 v0.3.1 原接口。单候选与父层继续调度仍走确定性快路径。

下方新增“同一份事实，四种判断方式”：改变根任务契约，选择是否需要观察资源，注入受控封路或合成等待。它使用同一物理引擎的冻结实验副本，不更改上方世界。结果、调用、问题、时间、单步模拟与实际轨迹可导出。四组对照始终离线，即使主游戏配置了模型。

推荐先用“为下一程补能”按四组离线对照：四种组织都用两步完成任务，但逐题调用与合批的请求数不同。再切换“尽快交付”看同一起点改变目标后的一步交付；勾选“初始资源未观测”检查实际读取过程。

## 真实模型

将 `.env.example` 复制为 `.env`，填入服务端 Jev 或兼容 Chat Completions 的 LLM 凭据。重启服务后，主游戏和新面板中可选择已配置模型。单文件与静态托管不会暴露密钥，也不会自动发送外部请求。错误不会偷偷回退为规则。

- 主游戏 `Jev + 本地生成`：S 使用 Jev，G 保持本地语法搜索。
- 主游戏 `Jev + LLM 技能提案`：S 用 Jev，G 使用现有受限技能提案接口。
- 实验副本 Jev / LLM：替换同一套判断任务后端，G 与任务契约不变。
- 未进行任何真实模型质量、价格或延迟测试；当前只有模拟协议证据。

```sh
npm run bench:judgments # 默认写 NOT_RUN，不发送请求
node scripts/benchmark-judgments.mjs --live --provider=jev --strategy=batch --task=energy --max-requests=12
```

脚本是小规模开发任务，不是完整统计基准。`--live` 会使用密钥产生费用，次数有硬上限；服务自身另有 `MAX_SERVER_CALLS` 上限。

## 开发与验收

```sh

npm run test:browser              # 需另装 Python Playwright 与 Chromium

```

构建不依赖在线 CDN，不包含字体文件。`docs/DESIGN-v0.4.md` 说明代码边界；`reports/GATE-v04.json` 与 `reports/VALIDATION-v031-v04.md` 指向本次证据。历史版本的报告保留作追溯，不能当作本版新跑结果。

## 不能据此宣称

合批不是免费算力，少请求不等于少 token，更不是智能提升；直接与拆分方法的问题与组合算法不同。只有相同拆分题目的合批/逐题对比隔离了请求调度。

图结构与规则判断器仍由开发者编写，尚未让 LLM 自己产生判断图。观察能力只在新任务夹具实现，未扩展至整个旧技能库。递归深度仍为一层。没有自动认知、自动进化、真正实时物理或生产安全保证。通过测试不是无缺陷保证。
