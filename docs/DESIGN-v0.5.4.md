# G/S Lab v0.5.4：同层调整优先，显式子问题可返回

## 1. 改变的对象

本版以 v0.5.3 为基线。原来的 AdaptiveGS 在每次 G 返回修订后建立更高层的“选择修订”问题；上层弃权后继续向上，深度耗尽直接传播到根。本版取消这种默认审批链，而不是扩大深度、强制接受单一候选或恢复参考求解器。

S 是快速、局部信息、不保证正确的选择器。G 同样可能出错。系统要允许 G 的配置实际进入试行，让 S 的选择和真实结果回到 G；不要求提前证明整个策略正确。

## 2. 默认运行协议

```
开始 / 首次单步
  → G 读取允许的初始世界、公开规则与未执行的动作草案
  → 一份决策条件更新
  → 结构与权限检查 + 当前阶段的有限声明一致性检查
  → 在原层装载为暂行条件（不改变世界）
  → 原层 S 选择实际候选，保留 none
  → 版本/权限/合法性复核 → 至多一个物理动作
  → 实际反馈；有需要时同层 G 再调整
```

初始化仍然必须先 G。新建、查看、订阅和刷新不会请求模型；首次 start/step 才开始。`g-before-action/v054` 的 ready 表示初始条件已经装载，不是策略有效认证，也不代表随后 S 必然选择动作。S 仍可能持续拒绝，使整个运行最终受限停止。

G 输出信封仍使用 `proposals`，但数组现在**恰好一项**。该项是“一套供 S 判断的条件”，其中可以有多个动作；不再是需要自动逐层审批的多个配置候选。输出多项会被明确拒绝，不能由程序取第一项或参考评分最高项。修订类型包括 `program`、`stage-update`、`subproblem`。结构检查不调用成功路径模拟。

同层 S 的 none 回到当前 G，附上真实 frame、answer、此前的应用/拒绝历史及允许的更广证据。G 可以换方案，不只重述旧方案。结构错误走 v0.5.2 定点格式纠错；声明不相容、版本不匹配等应用问题回到常规 G 调整，而不是锁住旧意图做格式修补。

## 3. 显式子问题

只有 G 明确返回 `kind=subproblem` 时才增加深度。`task` 必须给出 question、hypothesis、expectedResult、观察组、公开规则ID和本地 maxRevisions / maxGenerations。子问题没有世界执行器，没有修改父程序的权限，不是父更新的批准者。

子层仍用同一个 AdaptiveGS：先由子 G 形成 `kind=analysis` 的局部问题、观察范围和1～8个候选解释，再由子 S 选择；弃权时先在子层内部调整，也可以提出更深的明确子问题。

```
原层 G 请求一个子问题
  → 子 G 构造判断条件
  → 子 S 选择候选解释（或弃权后在子层改进）
  → 返回回答/未解决原因、实际选择、修订历史、已用生成额度
  → 原层 G 根据这个结果继续修改原来的上下文、选项或方案
```

`gs/subproblem-result/v054` 的 answered 仅表示选出了候选解释，不表示解释是真实世界事实。记录带 `epistemicStatus=model-judgment-not-world-fact`。未知解释、错误解释、失败结果都不能自动升级为事实或执行指令。当前子问题只做读操作下的语义诊断与候选解释选择，不是任意工具执行、通用逻辑证明或物理技能子任务。

## 4. 深度与预算

`maxDepth` 现在范围0～3，默认2：0关闭子问题展开，但不禁止根 G、同层修订或动作 S；1允许一个子问题层；2允许根0→子1→孙2。它不是修订审批层数、G调用次数或“智能等级”。

深度上限只拒绝该次展开。`subproblem_depth_exhausted`、本地修订/生成额度耗尽、未解决回答等作为子结果返回原层。原层在剩余额度中继续处理；相同问题/条件的重复子请求被去重。失败历史不清空、世界不回滚、预算不重新获得。

取消、世界版本变化、提供商错误、根请求/时间/生成预算耗尽不能伪装成普通分支失败继续执行。所有 G（含格式纠错与子层）和所有 S（含子问题选择）计入统一请求账本。一次 resolver 的全树生成上限仍与整局剩余 G 额度取小值；子任务不能放大这个额度。

`maxRevisions` 仍为每次解析中每层的有限尝试数，默认3；实际尝试包括合法但矛盾的配置和子问题请求，并非只计成功。`maxFormatRepairs` 只管单份输出额外的格式纠错，不提供免费请求。自然语言语义等价去重仍不能完全自动证明，所有额度继续限制空转。

## 5. 候选生命周期

三种含义明确区分：

| 配置 | 执行语义 |
|---|---|
| `candidateIds=null` + `kinds` | 每次依据当前世界重新枚举合法原语，再按 G 声明的类别过滤；不排序最佳路线 |
| 非空ID列表 + `candidateScope.mode=stage`，或旧格式省略 scope | 整个阶段持续使用固定白名单；不能静默扩大 |
| 非空ID列表 + `candidateScope={mode:snapshot,revision:...}` | 只针对该世界快照；版本变化后先触发 G，旧ID不能继续用于 S 或执行 |

`kinds` 不创造动作权限。目标坐标由 G 自己提出，几何距离不是最短可行路径。没有自动战术绑定、寻路、参考分数或环境前瞻搜索。

声明检查只针对当前阶段和可确定关系，包括：多个同时成立的不同位置条件；未满足的位置条件却不允许移动；持续移动白名单排除了所声明的目标格；正向资源/交付增量需要的能力被排除；快照ID过期或在该快照并不合法。

检查不补出正确路线，不移除限制后强行运行；错误交回 G 实质修改。未来阶段的起点尚未知，不提前断言其一定不可达。标题与正文的自然语言矛盾、长期资源计划等没有通用完备验证，仍是模型判断与实际反馈要处理的问题。

## 6. 试行与反馈

`adaptation_committed` 记录 `mode=same-layer-first/v054`、`status=provisional-not-proven`、`worldAction=false`。深度0事件应用根决策程序；analysis事件只改子判断条件。每个动作仍由动作 S 返回当前候选ID，none绝不改选概率第二名。

`stage-update` 保留已完成阶段、当前阶段起点和已用动作；配置更新不退款已消耗能量。替换程序也不能清除整局额度与真实动作历史。周期性复查记录 `reviewOnly/notProofOfError` 与真实位移：没有交付增量不等于已证明正在走错。

子问题结果与此前失败信息进入原 G 的允许证据。供应商推理流只读展示，不进入这些结果、S上下文或自学习记忆。

## 7. 可观测性和兼容

CLI/HTTP控制命令、唯一runId、幂等、接管和SSE保持。新增事件 `subproblem_enter`、`subproblem_return`、`same_layer_resumed`；G账本用途可为subproblem。旧 `meta_enter/meta_return` 仍可回放，但新默认流程不产生审批事件。

诊断增加 controlMode、candidatePolicy、subproblems；旧metaCalls字段保留兼容，现在计子问题S。输出统计中的committed含子问题条件的提交，分析根层应用时应按depth=0另计。界面维持概览/判断过程/诊断/配置四页签，显示同层调整、返回原因、候选生命周期和精确错误。

程序schema仍为gs/decision-program/v1（scope为可选扩展），输出contract为gs/adaptation-output-contract/v3。供应商继续使用原json_object参数，未宣称启用原生严格schema解码。自定义生成器需改成单更新输出；旧成功报告只读，不自动重新解释其旧审批语义。

## 8. 信息隔离与限制

自主lane没有参考控制器、解题示例、最优路线、优化投放坐标、参考模拟准入或历史参考记忆。公开规则不是参考答案。负向报告夹具仅存在tests/reports，不进入线上G/S。隔离是受信代码数据流约束，不是拥有全文件权限的恶意进程沙箱。

本版未调用真实Jev/LLM，不证明真实模型能形成正确策略、完整通关或智能随递归增长。默认本地动作轮换夹具仍不是求解器。没有自动归纳通用技能、在线权重训练、任意工具、无限层级、供应商金额硬预算或跨服务重启恢复活动会话。
