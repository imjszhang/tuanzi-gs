# 团子 / G/S Lab v0.3

**先完成 v0.2.1 证据与纠错修复，再引入参数化局部技能、一层真实子 G/S 和经验消费。**

本项目是可复现的 TypeScript 研究原型。默认全部离线：确定性规则选择器 + 有限语法搜索。语法、原语规则、参数绑定启发式及模拟器由开发者实现；阶段组合由搜索生成，不把它称作模型发现世界规律。

## 启动

直接打开 `play.html`。单文件不依赖网络、不使用密钥。或者安装 Node.js 22+，在此目录运行：

```sh
npm start
# 浏览器打开 http://127.0.0.1:4173
```

已经包含编译文件，启动不需要 `npm install`。修改源码后：

```sh
npm install
npm run build
npm test
npm run bench:v03
```

默认以“父子 G/S + 反应技能”进入守卫果园。在模型连接窗口可切换 v0.2.1 精确计划、完整规则、经验关闭/只记录/参与选择，以及需要真实接口的模式。

## 推荐的观察顺序

1. 第一次单步：父层缺少采集机会，有限语法搜索尝试局部阶段组合，形成 `gs/skill/v1`。此时只是通过模拟的试行提案，没有物理动作。
2. 下一步开始子 G/S。父层让出世界写入权，子层每步重新生成候选并选择动作。父子共享物理动作、推理请求、模拟检查和时间预算。
3. 子技能完成“创造采集机会”后返回父层。此时交付仍可能是 0/5。观察局部成功与根任务成功分别显示。
4. 根任务结束后切换镜像地图。同一个技能 ID/版本重新绑定对象和位置，不回放旧坐标；无关障碍也不要求重新生成整套技能。
5. “对照”保留完整预置规则、v0.2.1 完整序列搜索、v0.3 技能冷启动和继承记录后的暖启动。

镜像、物体移位和无关障碍只是声明范围内的有限测试，不证明所有新地图都能成功。自由编辑可以制造无解世界。

## 版本边界

| v0.2.1 | v0.3 |
|---|---|
| 完整有限行动序列 | 参数、注册谓词和有限阶段组成的局部技能 |
| 每步核对精确计划，包括最后一步 | 每步验证合法候选和真实效果，局部阶段内重新选择 |
| 任务成功与精确跟随分别记账 | 局部目标和根目标分别记账 |
| 多指标取舍不被“更短”自动淘汰 | 有条件的经验统计可以影响下一次技能选择 |
| 有界提案纠错 | 父/子均复用同一个 GSEngine，深度只允许 1 |

旧 Plan 并未删除，仍是确定性世界中的有效快速路径。v0.3 标准果园比精确计划更慢，代价和轨迹如实保留。

## 代码结构

```

src/skills/runtime.ts     父/子 GSEngine、执行权、共享预算、结果摘要
src/skills/catalogue.ts   有限语法搜索、局部运行记录
src/skills/experience.ts  结果均值/波动、off/record/use 消融
src/skills/providers.ts   同源模型桥接，无隐藏重试或降级

src/game/*               世界物理和独立根验收
vendor/gs-engine-ts/src  无游戏词汇的通用内核
server/reactive.mjs      新 Jev/LLM 请求协议与结构校验
```

## 真实模型（可选、有费用）

复制 `.env.example` 为 `.env`，仅在服务端填写真实密钥。启动后在“模型连接”中勾选费用确认再切换。密钥不会进入浏览器 bundle、模型上下文或导出轨迹。缺少配置时按钮禁用；调用失败不会冒充离线结果。

```sh
# 默认写入 NOT_RUN，不发外部请求
npm run bench:models

# 明确授权后运行；需要 env 凭据
# 全局最多 120 次请求尝试（可设置 MAX_BENCH_CALLS）
npm run bench:models -- --live --scenario=guarded
```

有凭据时，脚本比较 Jev+本地技能生成和 Jev+LLM 技能提案，记录任务结果、时间、搜索/验证工作量、真实 usage，并在相同捕获候选上比较 Jev 与配置的生成模型。候选选择“一致率”不是准确率，没有独立真值时不生成准确率。金额未知就为 null。结果写到 `reports/model-benchmark.json`。

本次交付没有执行真实模型评估，只有本地模拟 HTTP/响应协议测试。真实效能仍为 NOT_RUN。

## 验证与证据

见 `docs/VALIDATION-v0.3.md` 和 `reports/GATE-v03.json`；v0.2.1 已通过的阶段门保留在 `reports/GATE-v021.json`。

```sh
npm test
npm run bench:v03
npm run test:browser
npm run test:browser:legacy
```

浏览器自动化需另装 Python Playwright 和 Chromium，可设置 `CHROMIUM_PATH`。试玩不需要它们。自动化以 `set_content` 装载实际单文件字节；跨页面持久化使用 Storage 测试夹具，不声称证明实际 file:// 刷新或公网部署。HTTP 路由另由 Node 本地模拟服务检验。

`reports/` 保留原始轨迹、事件、对照数据和测试记录。旧版报告明确带旧版文件名，不作为新版本的测试结论。存储未经签名、防篡改或跨设备同步；读入的数据不能赋予权限。

## 有意未实现的能力

没有深层递归、L3 自动优化、从轨迹自动抽象技能、任意程序执行、线上强化学习、跨场景可靠性认证、独立实时物理时钟或生产级持久恢复。技能优先级/阶段规则里仍有开发者知识，不能声称“由 G/S 自发涌现全部智能”。

经验是有条件的历史表现，不是因果最优价值或校准成功概率。父层模型会在 use 模式收到相关统计，是否有效遵循必须通过真实评测检验；不能把上下文可见等同于已证明效果。
