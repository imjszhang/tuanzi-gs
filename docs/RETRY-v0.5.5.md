# v0.5.5 · Jev 有界传输重试

## 解决的范围

共享实验服务 `/lab` 中的 Jev 判断遇到短暂网络/服务错误时，不立即丢弃整场实验，而是在**同一个判断快照、同一个逻辑请求和同一场实验内**进行有界重试。适用于自主动作 S、显式子问题 S 和共享固定判断实验。G 生成请求不新增网络重试；裸 `/api/judgment` 单次传输入口保持一次调用，避免被多层重试放大。

重试不是 G/S 的语义修订。S 的合法 `none`、不理想的动作、低 confidence、不符合答案协议的完整响应，都不在该机制中重问。它们仍按既有的 G/S 或协议失败路径处理。不会换模型、切回规则、重跑 G、重置阶段或重放物理动作。

## 默认配置

| LabConfig | CLI | 默认 | 范围 |
|---|---|---:|---|
| jevMaxRetries | --jev-max-retries | 2 | 0–5，额外次数，总尝试=1+此值 |
| jevRetryBaseMs | --jev-retry-base-ms | 500 | 0–10000 |
| jevRetryMaxMs | --jev-retry-max-ms | 5000 | 0–30000，不能小于基数 |
| jevAttemptTimeoutMs | --jev-attempt-timeout-ms | 8000 | 100–25000 |

参数存入每场实验配置；网页高级设置可修改。旧命令自动采用默认值，`jevMaxRetries=0` 可作为无重试对照。没有 `.env` 隐藏覆盖。

指数退避带 50%–100% 抖动，指数项受 maxMs 限制。HTTP Retry-After（秒或日期）优先作为最小等待，不会为了上限提前重发；超过60秒则明确停止。等待受现有逻辑判断截止（自主 S 默认最多25秒）和根墙钟共同约束，不增加这些上限。配置3次尝试不保证在剩余时间内一定能发完3次。

## 分类

重试：HTTP 408、429、500、502、503、504；连接重置、连接拒绝、临时 DNS、连接/读取超时、Socket 中断；明确的单次访问超时。只对 Jev 生效。

不重试：400/401/402/403/404/422 等请求/凭据/额度错误；证书错误；缺配置；本地服务器或单局预算拒绝；完整但非法JSON/错误答案集合；S正常弃权；取消；世界快照过期。完整响应校验失败不被伪装成网络故障。

服务端仅给确定的传输错误附 `retryable` 元数据；宿主不凭错误字符串中的“502”猜测可重试性。网络错误信息不包含提供商响应正文或Authorization。

## 不重复行动与账本

每次尝试传相同的输入副本。每次发出前和返回后检查取消与世界版本；退避期间不推进世界。版本变化返回既有 stale 处理，首动作前重新研判时保留已用预算。

每个宿主发起的传输尝试独立占 `maxRequests`、`maxQuestions`、服务器调用上限和墙钟。失联的远端请求可能已被服务商计算或收费：不承诺服务商 exactly-once，不把未知 usage 填成0，不以延迟估计费用。宿主在开始/预约传输时保守计数；若等待服务器队列期间超时，宿主尝试次数可能大于服务器实际发出数，不能将其当作账单的精确计费次数。成功回答只交给引擎一次，实际动作仍经原执行边界提交。

`ledger.rows` 增加 logicalRequestId、attempt、maxAttempts、worldRevision、failureKind、providerStatus、retryable。一次逻辑 S 可以有多行传输尝试。判断调度的 requestAttempts 仍表示逻辑批次数，新增 `transportAttempts` 单独表示真实宿主尝试/题次；根实验账本始终按实际尝试计量。

`gs/s-retry/v1` 状态：attempting、waiting、recovered、failed、aborted，经 `s_retry` 事件与快照 `transportRetry` 输出。网页过程区展示等待与恢复，CLI/MCP可读取同一记录。恢复不是任务成功。重试额度用完为 `jev_transport_retries_exhausted`，仍明确结束本次有界运行；不偷偷新建实验。

## 验证与边界

测试使用本机 HTTP 模拟服务和显式测试选择器，不读取用户 `.env`，不调用真实 Jev/LLM。覆盖暂时失败后恢复、全部失败、Retry-After、超时、取消、过期状态、实际计账、none不重试、一个物理动作只执行一次。
